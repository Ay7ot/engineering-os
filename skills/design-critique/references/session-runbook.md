# Critique session runbook

Detail for running the session and keeping it useful across stages.

## Feedback by stage

Match the feedback to how settled the work is. Critiquing polish on a concept
wastes the session; critiquing information architecture after visual sign-off
reopens decided work.

| Stage | Focus on | Avoid |
|---|---|---|
| Early exploration | problem framing, conceptual direction, user needs alignment | visual polish, pixel detail, implementation |
| Mid fidelity | information architecture, user flows, interaction patterns | final copy, colour and font perfection, edge cases |
| High fidelity | visual consistency, accessibility, content quality, edge cases | reopening framing already validated |

## Facilitation tips

- Time management: set clear time boxes, run a visible timer, interrupt
  politely when a segment overruns.
- Participation: go around the room, invite the quiet, cap the loud by
  time-boxing shares.
- Focus: park tangents on a visible "parking lot" list and return to them at
  the end, summarise each segment before moving on.
- Documentation: capture all feedback, note priorities, assign an owner to each
  action item.

## Remote critique

- Keep everyone remote or everyone in the room; mixed modes cut out whoever is
  alone on the call.
- Share the design on screen and let reviewers annotate or comment directly.
- Mute when not speaking, keep video on for engagement.
- Record only with permission, then share the recording plus the written
  summary with anyone absent.

## After the session

- Send the summary while the session is fresh: what was reviewed, the themes,
  the decisions, the actions with owners.
- Close the loop later with reviewers on which notes were acted on and which
  were deliberately declined.
