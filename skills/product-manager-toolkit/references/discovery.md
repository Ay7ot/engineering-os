# Discovery: interviews, hypotheses, north star

For the research method itself (sampling, recruiting, synthesis), use the
`user-research` skill. This file is the PM-facing script and templates.

## Interview guide

| Segment | Time | Ask about |
|---|---|---|
| Context | 5 min | role, responsibilities, current workflow, tools used |
| Problem exploration | 15 min | pain points, how often, how much impact, current workarounds |
| Solution validation | 10 min | reaction to concepts, perceived value, willingness to pay |
| Wrap-up | 5 min | anything missed, referrals, permission to follow up |

Rules for the conversation:
- Ask about past behaviour, not future intentions.
- Ask why five times to reach the underlying problem.
- Do not ask leading questions; let the participant set the vocabulary.
- Interview in their environment where possible, and note emotional reactions.
- Record only with permission and store the transcript where the team can read
  it.

## Synthesis

1. Extract pain points and rank each by severity, plus how often it occurs.
2. Extract feature requests and mark which pain each one maps to.
3. Note jobs to be done, sentiment, competitor mentions, and the best quotes.
4. Group similar pain points across interviews and name the patterns.
5. Map the patterns to opportunity areas, then to candidate solutions.

## Hypothesis template

"We believe that building <feature or change> for <these users> will
<achieve this outcome>. We will know we are right when <metric>."

Each hypothesis names a change, a user, an outcome, and a measurable signal. If
any of the four is missing, it is not testable.

## North star metric

1. Identify the core value the product delivers.
2. Make that value measurable with one number.
3. Check it is actionable: moving it tells you something to do.
4. Check it is a leading indicator, not a lagging result.

Pair it with a small set of input metrics that the team can move directly.

## Pitfalls

- Solution-first thinking: features before the problem is understood.
- Analysis paralysis: more research instead of shipping a test.
- Feature factory: shipping without measuring impact.
- Metric theatre: optimising a vanity number that does not track value.
- Research that never becomes a decision; state what changed because of it.
